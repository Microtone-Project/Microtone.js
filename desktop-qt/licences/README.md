# Third-party notices of the desktop release

What every package of the Qt build carries beside `LICENSE.txt` (the GPL),
for the components that are not Microtone's. A release without these is a
release that breaks its dependencies' licences, so a package is not made
without them: each CI job runs `tools/collect-notices.js`, and
`microtone-worker/test/node/third-party-notices.test.js` pins the wiring.

## What is here

| File | What it is |
|---|---|
| `THIRD-PARTY-NOTICES.txt` | The notice itself, a TEMPLATE: `@VERSION@`, `@QT_VERSION@`, `@QT_SERIES@`, `@RTAUDIO_VERSION@`, `@RTMIDI_VERSION@`, `@MONOCYPHER_VERSION@`, `@LINUX_LIBRARIES@`, and `{{#windows}} … {{/windows}}` blocks (`{{#linux macos}}` for several) per platform. Plain text, wrapped, so that Notepad reads it. |
| `qtwebengine-third-party.txt` | Chromium's third-party notices as Qt WebEngine 6.11 lists them: 126 components with homepage, licence and copyright lines. GENERATED by `tools/qtwebengine-credits.js` from Qt's documentation; commit the result. |
| `texts/LGPL-3.0.txt`, `LGPL-2.1.txt` | gnu.org's texts (Qt: LGPL 3; FFmpeg inside Chromium: LGPL 2.1). |
| `texts/ICU-73.2-LICENSE.txt` | ICU's licence, release 73.2 (Linux: the ICU in Qt's own installation). |

RtAudio's, RtMidi's and Monocypher's licences are the vendored files themselves
(`../vendor/rtaudio/LICENSE`, `../vendor/rtmidi/LICENSE`, `../vendor/monocypher/LICENCE.md`), copied into
the package at build time, never kept twice. The GPL (for Microtone, and for
the ASIO SDK, which Steinberg offers under it since 2025-10-15) is the
repository's `COPYING`, which each job already puts in as `LICENSE.txt`.

## What a package gets

`tools/collect-notices.js --platform <p> --out <dir> --qmake <qmake>` writes
`THIRD-PARTY-NOTICES.txt` and `licences/` into `<dir>`:

- **Windows**: the packaged folder's root (installed with the rest; the file
  lists of the installer and the uninstaller are made from the folder).
- **macOS**: `Microtone.app/Contents/Resources`, before `macdeployqt` and the
  signature seal the bundle.
- **Linux**: `usr/share/doc/microtone` of the tree (so `/opt/microtone/share/
  doc/microtone` in the .deb and .rpm), made by `linux-package.sh` after it
  has removed the libraries it leaves to the system.

Besides the files above, every package gets `licences/qt-components.txt`, made
from the SBOMs (`<Qt>/sbom/*.spdx.json`) that Qt installs beside itself: what
Qt carries inside its libraries (libpng, PCRE2, HarfBuzz, the Wayland
protocols …) with licence and copyright lines, for the modules this app
deploys (`SBOM_MODULES`) and without the tests and tools. A Qt without SBOMs
leaves a note pointing to Qt's documentation instead, and a warning.

**Linux credits what the tree really carries.** Every library file in `lib/`
that is not `libQt6*` goes through `dpkg -S` on the build system: the owning
package's `/usr/share/doc/<package>/copyright` is copied to
`licences/debian/<package>/`, along with the common licences it cites
(`/usr/share/common-licenses/…`), and the section of the notices names the
package, its version, its source package and where to get the source. The
libraries of Qt's own installation are ICU's (credited with `texts/ICU-…`);
any other, and any library no package owns, stops the build. So a library
that linuxdeploy starts to carry is either credited or stops CI — it cannot
slip into a release unnamed. Libraries the package leaves to the system
(glibc, X11, NSS, Wayland, JACK …) need nothing: they are not distributed.

## When something changes

- **Qt moves to another minor** (6.12): run `node desktop-qt/tools/qtwebengine-credits.js
  --qt 6.12`, commit the file. The test fails until `qtwebengine-third-party.txt`
  and the workflow's Qt agree. The notice says "Qt WebEngine 6.12 lists"
  for itself.
- **A library is vendored** (`../vendor/`): give it a `## Name version` heading
  in `VENDOR-VERSIONS.md` (the test reads it) and a section here in the
  template, with its licence file copied by `collect-notices.js`.
- **windeployqt / macdeployqt start to bring something else** (a codec, a
  compiler runtime): it needs a section, as the C runtime has. Nothing checks
  those two folders automatically; look at the artifact when you touch their flags.
- **ICU moves** with Qt's installation: its release is named in the template,
  `collect-notices.js` and `texts/`; replace all three.
- **A different licence for the app**: the notices say that Steinberg's GPL
  grant is what lets the Windows build carry ASIO, and that anyone distributing
  it under other terms needs Steinberg's own licence (the same position as
  `../vendor/VENDOR-VERSIONS.md`). Both texts say it; change both.

## Not covered here

The web app inside the package (`www/`) has its own third-party material — the
typefaces, fflate, fzstd, Zstandard, Pyodide and NumPy. Those are the web
app's, shipped on the website too, and are not in these notices.
